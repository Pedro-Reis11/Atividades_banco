Respostas dos Exercícios de SQL (DDL) — MySQL

Este documento contém os comandos SQL (Data Definition Language - DDL) correspondentes à resolução dos exercícios solicitados, utilizando exclusivamente a sintaxe do MySQL.

1. Adicionar data_fabricacao NOT NULL na tabela Padaria_Pao

ALTER TABLE Padaria_Pao 
ADD COLUMN data_fabricacao DATE NOT NULL;


2. Adicionar coluna opcional observacao (até 200 caracteres) na tabela Padaria_Pao

ALTER TABLE Padaria_Pao 
ADD COLUMN observacao VARCHAR(200);


3. Na mesma tabela, adicione uma coluna opcional observacao, com tamanho máximo de 200 caracteres

(Caso seja executado em conjunto com as alterações da tabela Padaria_Pao):

ALTER TABLE Padaria_Pao 
ADD COLUMN observacao VARCHAR(200);


4. Alterar o tamanho da coluna nome para permitir 120 caracteres

ALTER TABLE Padaria_Pao 
MODIFY COLUMN nome VARCHAR(120);


5. Renomear a coluna valor_venda para preco sem alterar seu tipo

(Suportado no MySQL 8.0+):

ALTER TABLE Padaria_Pao 
RENAME COLUMN valor_venda TO preco;


(Para versões do MySQL anteriores à 8.0, deve-se redefinir o tipo junto com o CHANGE):

-- Alternativa para MySQL < 8.0 (assumindo tipo DECIMAL(10,2))
ALTER TABLE Padaria_Pao 
CHANGE COLUMN valor_venda preco DECIMAL(10,2);


6. Adicionar a coluna peso_gramas logo após a coluna nome

ALTER TABLE Padaria_Pao 
ADD COLUMN peso_gramas INT AFTER nome;


7. Alterar o preço padrão do produto para o valor 0,00 na tabela da padaria

ALTER TABLE Padaria_Pao 
ALTER COLUMN preco SET DEFAULT 0.00;


8. Remover o valor padrão da coluna peso_gramas

ALTER TABLE Padaria_Pao 
ALTER COLUMN peso_gramas DROP DEFAULT;


9. Remover da tabela de padaria a coluna codigo_interno que não é mais utilizada

ALTER TABLE Padaria_Pao 
DROP COLUMN codigo_interno;


10. Na tabela Farmacia_Medicamento, tornar a coluna principio_ativo obrigatória

(No MySQL, para adicionar NOT NULL a uma coluna existente, utiliza-se MODIFY repetindo o tipo de dado):

ALTER TABLE Farmacia_Medicamento 
MODIFY COLUMN principio_ativo VARCHAR(255) NOT NULL;


11. Adicionar à tabela de medicamentos uma restrição que impeça o estoque de receber valores negativos

(Suportado a partir do MySQL 8.0.16):

ALTER TABLE Farmacia_Medicamento 
ADD CONSTRAINT chk_estoque_nao_negativo CHECK (estoque >= 0);


12. Criar uma restrição única para impedir medicamentos com o mesmo código de barras

ALTER TABLE Farmacia_Medicamento 
ADD CONSTRAINT unq_codigo_barras UNIQUE (codigo_barras);


13. Remover da tabela de medicamentos a restrição única criada no exercício anterior

(No MySQL, restrições UNIQUE e índices únicos são removidos utilizando a sintaxe DROP INDEX):

ALTER TABLE Farmacia_Medicamento 
DROP INDEX unq_codigo_barras;


14. Adicionar à tabela Medicamento_Venda uma chave estrangeira relacionando o medicamento ao respectivo registro da tabela Farmacia_Medicamento

ALTER TABLE Medicamento_Venda 
ADD CONSTRAINT fk_medicamento_venda 
FOREIGN KEY (medicamento_id) 
REFERENCES Farmacia_Medicamento(id);


15. Remover essa chave estrangeira sem remover a coluna que contém o identificador do medicamento

ALTER TABLE Medicamento_Venda 
DROP FOREIGN KEY fk_medicamento_venda;


16. Criar um índice para acelerar consultas pelo nome da agência de viagens

CREATE INDEX idx_agencia_nome 
ON Agencia_Viagem (nome);


17. Adicionar uma chave primária à tabela Viagem formada pelas colunas codigo_pacote e data_saida

ALTER TABLE Viagem 
ADD CONSTRAINT pk_viagem PRIMARY KEY (codigo_pacote, data_saida);


18. Remover temporariamente a chave primária da tabela Viagem e explicação dos perigos

Comando MySQL:

ALTER TABLE Viagem 
DROP PRIMARY KEY;


Por que essa operação pode ser perigosa?

Risco de Duplicação e Perda de Integridade: Sem a chave primária, o MySQL deixa de garantir a unicidade dos registros. Isso permite a inserção acidental de viagens com a mesma combinação de codigo_pacote e data_saida.

Impacto na Performance: A Primary Key no MySQL (engine InnoDB) define o Clustered Index da tabela. Ao removê-la, o MySQL precisa reorganizar fisicamente a tabela e seus índices, o que causa alto custo de processamento e lentidão extrema nas buscas.

Quebra de Relacionamentos: Se existirem outras tabelas com chave estrangeira (FOREIGN KEY) referenciando esses dois campos em Viagem, o MySQL impedirá a remoção ou a integridade referencial do sistema será seriamente comprometida.

19. Renomear a tabela Cliente_Viagem para Turista

RENAME TABLE Cliente_Viagem TO Turista;


20. Adicionar simultaneamente uma coluna ativo e um índice pelo campo destino na tabela de pacotes turísticos

ALTER TABLE Pacote_Turistico 
ADD COLUMN ativo BOOLEAN DEFAULT TRUE,
ADD INDEX idx_pacote_destino (destino);


21. Escreva uma sequência de alterações que aumente o tamanho de um campo de e-mail, renomeie esse campo para email_contato e adicione uma restrição única

(Comando unificado no MySQL para otimizar tempo de execução na tabela):

ALTER TABLE Usuario 
MODIFY COLUMN email VARCHAR(150),
RENAME COLUMN email TO email_contato,
ADD CONSTRAINT unq_email_contato UNIQUE (email_contato);
