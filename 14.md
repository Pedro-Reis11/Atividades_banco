## 5) Renomear a coluna `valor_venda` para `preco` sem alterar seu tipo

**MySQL 8.0+:**

```sql
ALTER TABLE Padaria_Pao
RENAME COLUMN valor_venda TO preco;
```

**Alternativa para MySQL < 8.0** (é preciso redefinir o tipo junto com o `CHANGE`; aqui assumindo `DECIMAL(10,2)`):

```sql
ALTER TABLE Padaria_Pao
CHANGE COLUMN valor_venda preco DECIMAL(10,2);
```

## 10) Na tabela `Farmacia_Medicamento`, tornar a coluna `principio_ativo` obrigatória

## 18) Remover temporariamente a chave primária da tabela `Viagem` e explicar os perigos

```sql
ALTER TABLE Viagem
DROP PRIMARY KEY;
```

**Por que essa operação pode ser perigosa?**

- **Risco de duplicação e perda de integridade:** sem a chave primária, o MySQL deixa de garantir a unicidade dos registros. Isso permite a inserção acidental de viagens com a mesma combinação de `codigo_pacote` e `data_saida`.
- **Impacto na performance:** a *Primary Key* no MySQL (engine InnoDB) define o *Clustered Index* da tabela. Ao removê-la, o MySQL precisa reorganizar fisicamente a tabela e seus índices, o que causa alto custo de processamento e lentidão extrema nas buscas.
- **Quebra de relacionamentos:** se existirem outras tabelas com chave estrangeira (`FOREIGN KEY`) referenciando esses dois campos em `Viagem`, o MySQL impedirá a remoção, ou a integridade referencial do sistema será seriamente comprometida.

## 21) Aumentar o tamanho do campo de e-mail, renomeá-lo para `email_contato` e adicionar restrição única

> Comando unificado no MySQL para otimizar o tempo de execução na tabela.

```sql
ALTER TABLE Usuario
MODIFY COLUMN email VARCHAR(150),
RENAME COLUMN email TO email_contato,
ADD CONSTRAINT unq_email_contato UNIQUE (email_contato);
```

**Alternativa mais segura**, usando `CHANGE COLUMN` (redefine tipo e nome de uma só vez):

```sql
ALTER TABLE Usuario
CHANGE COLUMN email email_contato VARCHAR(150),
ADD CONSTRAINT unq_email_contato UNIQUE (email_contato);
```
