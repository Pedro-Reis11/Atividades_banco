# Respostas dos Exercícios SQL - DELETE

> Recomenda-se executar os comandos dentro de transações durante os testes:
>
> ```sql
> START TRANSACTION;
> -- comandos DELETE
> ROLLBACK;
> ```
>
> Quando tiver certeza do resultado:
>
> ```sql
> COMMIT;
> ```

---

# Exercício 1 — Produto

## a) Excluir o produto de id = 5

```sql
DELETE FROM Produto
WHERE id = 5;
```

---

## b) Excluir os produtos 6 e 7 usando IN

```sql
DELETE FROM Produto
WHERE id IN (6, 7);
```

---

## c) Excluir produtos que contenham "cola"

```sql
DELETE FROM Produto
WHERE nome LIKE '%cola%';
```

---

## d) Excluir todos os produtos do fornecedor 11111111000101

```sql
DELETE FROM Produto
WHERE cnpj_fornecedor = '11111111000101';
```

### Quantas linhas serão afetadas?

Nos dados fornecidos:

| id | produto |
|----|----------|
| 1 | Arroz Tipo 1 5kg |
| 2 | Feijao carioca 1kg |

**2 linhas serão excluídas.**

### Isso seria arriscado?

Sim.

Em sistemas reais um fornecedor pode possuir centenas ou milhares de produtos. Um DELETE amplo pode remover dados importantes acidentalmente e causar perda de informações de estoque, vendas e histórico.

---

## e) DELETE dentro de transação

```sql
START TRANSACTION;

DELETE FROM Produto
WHERE id = 4;

ROLLBACK;
```

### Explicação

Com `ROLLBACK`, a exclusão é cancelada e o produto permanece na tabela.

Se fosse utilizado:

```sql
COMMIT;
```

a exclusão seria definitivamente gravada no banco de dados.

# Exercício 2 — Pedido

## a) Excluir pedido id = 6

```sql
DELETE FROM Pedido
WHERE id = 6;
```

---

## b) Excluir pedidos 1 e 5

```sql
DELETE FROM Pedido
WHERE id IN (1, 5);
```

---

## c) Excluir pedidos entregues

```sql
DELETE FROM Pedido
WHERE status = 'entregue';
```

---

## d) Excluir o pedido com maior quantidade

### Conferindo qual é o maior

```sql
SELECT *
FROM Pedido
ORDER BY quantidade DESC
LIMIT 1;
```

### Exclusão

```sql
DELETE FROM Pedido
ORDER BY quantidade DESC
LIMIT 1;
```

---

## e) Exclusão lógica (Soft Delete)

Em sistemas reais normalmente não se remove o pedido fisicamente.

Em vez disso:

```text
status = 'cancelado'
```

Vantagens:

- Mantém histórico de vendas.
- Permite auditoria.
- Facilita relatórios.
- Evita perda de informações do cliente.
- Possibilita análise de cancelamentos.

# Exercício 3 — Pacote

## a) Excluir pacote Bonito - MS

```sql
DELETE FROM Pacote
WHERE id = 5;
```

---

## b) Excluir pacotes inativos e sem vagas

```sql
DELETE FROM Pacote
WHERE ativo = 0
  AND vagas = 0;
```

---

## c) Excluir pacotes acima de R$ 2.000,00 usando subquery

```sql
DELETE FROM Pacote
WHERE id IN (
    SELECT id
    FROM (
        SELECT id
        FROM Pacote
        WHERE preco > 2000.00
    ) AS pacotes_caros
);
```

---

## d) Exclusão em transação

```sql
START TRANSACTION;

DELETE FROM Pacote
WHERE id IN (
    SELECT id
    FROM (
        SELECT id
        FROM Pacote
        WHERE preco > 2000.00
    ) AS pacotes_caros
);

SELECT *
FROM Pacote;

ROLLBACK;
```

Após verificar:

```sql
COMMIT;
```

ou

```sql
ROLLBACK;
```

---

## e) Integridade referencial

Se existirem reservas associadas ao pacote:

```text
Reserva -> Pacote
```

Excluir o pacote pode deixar reservas órfãs.

Uma chave estrangeira como:

```sql
FOREIGN KEY (id_pacote)
REFERENCES Pacote(id)
ON DELETE RESTRICT
```

impediria a exclusão enquanto houver reservas relacionadas.

# Exercício 4 — Conta

## a) Excluir conta 1004

```sql
DELETE FROM Conta
WHERE numero = 1004;
```

---

## b) Excluir contas sem telefone

### Conferência

```sql
SELECT *
FROM Conta
WHERE telefone IS NULL;
```

### Exclusão

```sql
DELETE FROM Conta
WHERE telefone IS NULL;
```

---

## c) DELETE sem WHERE

```sql
DELETE FROM Conta;
```

### Por que é perigoso?

Esse comando remove todas as contas da tabela.

Em uma instituição financeira isso poderia causar:

- Perda de histórico bancário.
- Problemas legais.
- Quebra de auditorias.
- Paralisação do sistema.
- Perda irreversível de dados.

---

## d) Transação com ROLLBACK

```sql
START TRANSACTION;

DELETE FROM Conta
WHERE numero = 1004;

ROLLBACK;
```

Após o rollback:

```sql
SELECT *
FROM Conta
WHERE numero = 1004;
```

A conta continuará existindo.

---

## e) Reflexão

Bancos normalmente não excluem fisicamente contas encerradas.

O comum é possuir campos como:

```text
status = 'encerrada'
ativo = FALSE
data_encerramento
```

Isso é importante para:

- Auditorias.
- Fiscalizações.
- Prevenção a fraudes.
- Cumprimento de exigências legais.
- Preservação do histórico financeiro.

# Exercício 5 — Filial e Estoque

## a) Excluir apenas o produto 1 da filial 20202020000120

Como a chave é composta:

```sql
DELETE FROM Estoque
WHERE id_produto = 1
  AND cnpj_filial = '20202020000120';
```

---

## b) Excluir itens esgotados

```sql
DELETE FROM Estoque
WHERE quantidade = 0;
```

---

## c) Excluir produtos do fornecedor 11111111000101 usando subquery

```sql
DELETE FROM Estoque
WHERE id_produto IN (
    SELECT id
    FROM (
        SELECT id
        FROM Produto
        WHERE cnpj_fornecedor = '11111111000101'
    ) AS produtos_fornecedor
);
```

---

## d) Exclusão da filial com registros relacionados

Tentativa:

```sql
DELETE FROM Filial
WHERE cnpj = '10101010000110';
```

### O que deveria acontecer?

Se existir chave estrangeira:

```sql
FOREIGN KEY (cnpj_filial)
REFERENCES Filial(cnpj)
```

o banco deverá impedir a exclusão.

### Melhor opção

```sql
ON DELETE RESTRICT
```

Motivo:

Impede a remoção de uma filial que ainda possui estoque relacionado.

Evita perda acidental de dados.

---

## e) Exclusão em sequência usando transação

```sql
START TRANSACTION;

DELETE FROM Estoque
WHERE cnpj_filial = '10101010000110';

DELETE FROM Filial
WHERE cnpj = '10101010000110';

SELECT *
FROM Filial;

SELECT *
FROM Estoque;

ROLLBACK;
```

Após conferir:

```sql
COMMIT;
```

ou

```sql
ROLLBACK;
```

### Por que a ordem importa?

Se a chave estrangeira estiver configurada com:

```sql
ON DELETE RESTRICT
```

não será possível excluir primeiro a filial.

Primeiro devem ser removidos os registros dependentes em `Estoque`.

Somente depois a filial poderá ser removida sem violar a integridade referencial.
